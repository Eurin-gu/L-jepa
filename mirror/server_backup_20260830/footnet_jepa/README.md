# JEPA-FootNet proxy benchmark

This project tests whether masked latent pretraining improves a neural emulator
of a receptor-conditioned atmospheric back-trajectory shape.

## Current contract

```text
input  = receptor query
       + 4 times x [U10M, V10M, PBLH, PRSS]
       + receptor-relative metric coordinates

target = unit-mass 24 h horizontal trajectory-residence distribution
```

HRRR fields and OCO-2 receptor locations are real. The target is generated by a
horizontal particle proxy, not STILT/X-STILT and not a physical-unit footprint.
PBLH and PRSS are currently input covariates but do not affect the proxy target.

The proxy output uses a spatial softmax and distribution loss. Physical STILT
footprints use schema v5, a softplus amplitude output, and a separate pixel +
mass + shape-KL loss; the two contracts cannot be loaded interchangeably.

## Run

```bash
./run_smoke.sh
python3 -m unittest discover -s tests -q
```

The smoke run rebuilds 12 April train and 6 July test receptors at 64x64, then
trains one seed. It verifies the pipeline only.

For an expanded run:

```bash
export FOOTNET_DATA_DIR=/path/on/large/disk
export FOOTNET_RECEPTORS=random
./run_full.sh
```

Set `AUTO_SPLIT=True` only after adding independent HRRR dates. OCO-2 receptor
mode requires a matching `sounding_manifest_YYYYMMDD.json` for every selected
snapshot; use random receptors for dates without manifests.

Each training invocation writes an immutable `results/<run-id>/` containing
per-seed checkpoints, metrics, source fingerprint, and data-contract fingerprint.
Files directly under `results/` are invalid historical artifacts; see
`results/README.md`.

## Interpretation limits

- Random receptors from one HRRR snapshot are not independent weather samples.
- The current proxy omits vertical motion, surface influence, convection,
  deposition, and physical footprint units.
- Generic spatial JEPA is implemented. A Lagrangian-JEPA prototype exists in
  `lagrangian_jepa.py`, but it still uses proxy trajectories and is not yet the
  final STILT-based arm. Met-MAE, STILT labels, cross-region tests, and
  cross-resolution tests are not yet implemented.
- The train-mean footprint is a mandatory zero-parameter baseline. A learned
  model that does not beat it has not demonstrated useful transport skill.
- `train_stilt_strict.py` additionally holds out dates and spatial tiles,
  pairs all arm initializations/minibatch order, and reports sparse-footprint,
  mass, overlap, correlation, center, and peak metrics.

## Lagrangian-JEPA prototype

`lagrangian_jepa.py` contains an initial trajectory-aware JEPA implementation:

- `compute_trajectory_xy()`: samples a mean backward trajectory using real HRRR winds.
- `TrajectoryPredictor`: predicts masked trajectory features from visible trajectory features.
- `LagrangianJEPA`: JEPA-style masked prediction along trajectories.

Run a small prototype:

```bash
python3 train_lagrangian_jepa.py --smoke --epochs 2
```

The primary arm must use a trajectory computable from inputs at deployment
(`input_wind_trajectory`). A STILT/X-STILT `traj.rds` generated by the same
solve as the footprint is useful only as a clearly named privileged ablation;
it is not an answer-free self-supervised input.

## STILT/X-STILT data generation

`autodl_stilt_setup.sh` is a template for installing STILT/X-STILT on Autodl.
It does not download large met/observation data automatically. You need to:

1. Download ARL-format HRRR/GDAS met fields.
2. Download matching OCO-2 Lite files.
3. Edit `X-STILT/run_xstilt.r`.
4. Run `Rscript run_xstilt.r`.
5. Point `data_builder.py` at the resulting `foot.nc` and `traj.rds` files.
